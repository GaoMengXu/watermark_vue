## 新增文档互转工具（/doc-convert）
- 纯本地 Word↔PDF 双向转换。新增 `src/views/DocConvertView.vue` + `src/utils/docConvert.js`，在 `tools.js` 注册（首页与水印并列显示）。
- Word→PDF：`docx-preview`（渲染 DOM，className=`docx-page`，inWrapper:false）→ `html2canvas` 逐 `section.docx-page` 截图 → `jspdf` 拼多页 PDF。
- PDF→Word：`pdfjs-dist` 逐页 `getTextContent` 提取文字 → `docx` 生成 .docx（仅文本+段落，不还原表格/图片/字体）。
- **关键坑**：pdfjs-dist v4 标准 build 的 ESM worker 在 Vite 下加载失败（`getDocument` 卡住）。改用 `pdfjs-dist/legacy/build/pdf.mjs` + `legacy/build/pdf.worker.min.mjs?url` 解决，`watermark.js` 一并切换（顺带修复其 PDF 预览一直降级 embed 的问题）。
- 测试：用 CDP 协议真实等待验证，Word→PDF 产出 76KB PDF、PDF→Word 提取 2 页 132 字，双向通过。注意：Chrome `--virtual-time-budget` 无法推进 pdfjs worker 异步，测 worker 逻辑要用真实等待（CDP 或 Node 直接跑 pdfjs）。

## 扫描件 OCR（PDF→Word 自动降级）
- 用户反馈：扫描型 PDF（无文字层）转 Word 失败。用 pdfjs 检查 `text items: 0` 确认是图片型扫描件。
- 集成 `tesseract.js@7` 做纯前端 OCR（中文 `chi_sim` + 英文 `eng`），PDF 文字层为空时自动降级 OCR。
- 资源本地化到 `public/`：`tessdata/`（chi_sim + eng 的 .gz 语言包，从 unpkg `@tesseract.js-data` 下载）、`tess-core/`（worker.min.js + tesseract.js-core 的 wasm 系列）。`getOcrWorker` 用 `workerPath`/`corePath`/`langPath` 全部指向本地，`gzip:true`。
- **关键 bug**：pdfjs `getDocument({ data })` 会把传入的 Uint8Array 底层 buffer transfer 给 worker，导致原 ArrayBuffer detached；同一 File 重复 `arrayBuffer()` + 二次 getDocument 报 `Cannot perform Construct on a detached ArrayBuffer`。修复：所有 `extractPdfText`/`ocrPdfToText`/`renderPdfPageToCanvas` 内部用 `arrayBuffer.slice(0)` 独立副本；`handleFile` 里 PDF 只读一次 arrayBuffer 复用。
- 验证：真实采购订单扫描件 OCR 成功识别出公司名/银行/订单内容（"已就绪可导出"）。

## 修复 xlsx 转 PDF 失败（html2canvas "Unable to find element in cloned iframe"）
- 用户反馈：真实 Excel「工作簿1.xlsx」（3 sheet、81 行，含多行文本的"服务内容"列）转 PDF 报"处理失败，请换一个文件重试"。
- 根因：`domToPdfBlob` 直接对页面 flex 布局里的 `section.sheet-page` 调 `html2canvas`，抛出 `Unable to find element in cloned iframe`（html2canvas 对页面流内复杂元素的已知 bug，且单 sheet 高度达 6132px 超一页 A4）。
- 修复：`domToPdfBlob` 重写为「离屏克隆」——把目标元素 `cloneNode(true)` 到绝对定位(left:-99999px)的离屏容器再截图，规避页面布局干扰；同时对超高元素按 A4 高度纵向切片分页；`.sheet-page` 的 `overflow:auto` 改为 `visible`。
- 验证：真实 xlsx 产出有效 PDF（%PDF 头、3 sheet 81 行、2.8MB）；docx/pptx 回归测试通过（离屏方案未破坏其他格式）。
- 备注：`handleFile` 的 catch 加了 `console.error` 便于后续排查（此前 e.message 为空导致只显示兜底文案）。
